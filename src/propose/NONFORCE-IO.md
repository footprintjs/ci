# Closed native proposal effect IO

This internal layer binds one exact request on the SAME captured HTTP owner for
native blob, tree, commit, nonforce release/next movement and release/next-to-main
PR creation. It returns bounded provider data and finite attempt state. Neither
a closed payload, returned HTTP bytes, an opaque owner, a request port nor a
saved record grants native eligibility or reconciliation.

The owning shared Propose flow still owes the independently reconstructed
package/profile, B/M/P/L and raw queue, at most eight independently bound pending
witnesses, actual current writer/source/producer, reviews/refusals, retained
history/grants/reservations/submission checks, an actual committed pre-effect
stage and immediate repository rechecks before EACH mutation. No physical
workflow caller or complete owning nonforce flow adopts these ports yet.

Request bodies permit no custom commit author/committer/signature, force=true,
arbitrary ref, PR branch, auto-merge field or publication endpoint. Tree paths
and modes are closed, duplicate paths and duplicate ordered parents refuse.
The tree/commit/ref/PR slots are each single-attempt in this captured invocation.
Blob slots are keyed by exact Git blob identity: distinct content can be created,
but repeated identical content must reuse its independently verified result.
Request payloads are detached before any await.

Every mutation request body and every response charges the SAME admitted-byte
bank already shared with native GET and registry observations. The hard global
bounds remain 4,096 requests and 128 MiB, and caller bounds may only be lower.
Structured effect payloads retain the existing one-MiB JSON admission boundary.
Native blob content has a narrow typed UTF8-string boundary of two MiB; its
serialized JSON body is separately capped at four MiB. The shared ledger/JSON
reader's ceiling is unchanged. These are byte/admission bounds, not absolute
socket or heap guarantees.

Only creation HTTP201 or ref/metadata setter HTTP200 means returned bytes, never
a parsed, correctly identified or reconciled effect. The owning native flow must
validate exact Git OIDs/tree/ordered parents/App actor and PR facts. A malformed
JSON response is technical failure. Narrow fetch uncertainty, failed mutation or
parse failure stops further mutations on this owner; bounded GET verification
remains available unless its ordinary budget is exhausted. There is no local
journal, saved grant, replacement credential or retry through another view.

The request lock is ephemeral. It cannot remember or authorize a later invocation.
The full native history must independently HOLD unknown non-idempotent outcomes
across invocations, with GET verification only and no inferred-absence replay.
C1's exact PR metadata setter remains a separate idempotent effect: a later
invocation with ALL fresh native predicates may one identical PATCH.
