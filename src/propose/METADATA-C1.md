# Internal C1 metadata reconciliation


The private source module `foottrace-metadata-reconciliation.mjs` composes the
CODE-selected writer capture, source prefix, ordinary preparation, signed current
App ref, native reviews, retained workflows and attempts, candidate reservations
and publication checks, and the existing CI/tested-tree/CodeQL policy in one
native executor. It checks that executor's actual committed pre-effect row,
reacquires all repository predicates through the same writer owner, and then
takes the native no-op or exact title/body PATCH branch. App identity remains
this job's start observation; no private-App port, new key consumer or signing
child exists.

A returned response must retain the bound PR, App author, repositories, head,
base and exact metadata. A known inconsistent or unparsable response stays a
technical failure. Only narrowly classified submission uncertainty permits
GET-only reconciliation: exact GET completes, verified stale metadata holds
this invocation, and a later invocation reconstructs every predicate before
one identical PATCH. Authorization, acquisition and verification failures stay
technical. Native partial records retain finite diagnostic attempt state and
completed rows; they are never continuation inputs or saved authority.

This module is internal source work, exercised through synthetic provider
fixtures. It is not exported by the compiled read-only bootstrap and has no
physical workflow caller. The actual pinned writer-action output to capture
handoff, physical workflow/eco output consumption, remaining Propose effects,
complete source review and hosted gates are still required.
Metadata match grants no release readiness, publication or ref authority.

The CODE-selected runFoottraceMetadataReconciliationWithOutput entry reuses the
same controller. It checks that its own executor committed the actual native
terminal, reads the recorded verification/terminal values for native provenance,
then awaits one fixed summary and one fixed proposeOutcome line. The no-output
entry ignores supplied append callbacks. The matching value is
metadata-matched, exactly the spelling consumed by the existing business gate.

One fixed text/IO core serves this actual terminal composition and the older
negative diagnostic wrapper. The negative wrapper keeps its runtime signal and
cross-writer attempt guards. Neither a text enum, saved record, runtime brand nor
IO success admits a terminal or provider authority. A partial or failed append
stays technical, with a finite diagnostic partial-save flag and no append retry.
Reported match still requires the separately observed successful provider job to
pass the business predicate; it clears no other eco hold and grants no release
readiness. This source is not exported/adopted by the physical workflow.
