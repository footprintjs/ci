# Whole native terminal output (private source WIP)

runFoottraceProposalWithOutput uses the SAME captured writer owner, native
executor and chart as runFoottraceProposal. Its CODE-selected local summary and
output ports must be valid before provider mutations. No DATA field selects a
factory, executor, outcome, terminal or permission. The no-output entry ignores
supplied output callbacks.

After the selected C1, pending REF or ordinary recipe commits its actual native
terminal, the whole terminal reads that recipe's native result through scope.
A closed report mapper validates the finite status and result facts. The output
stage reads the whole result, verifies both actual completed stages and checks
the selected native facts again. It awaits the existing one-attempt output core:
summary first, then the exact machine line.

| Actual native outcome | Exact machine line |
| --- | --- |
| Metadata matched or known complete proposal | proposeOutcome=metadata-matched |
| Verified stale metadata | proposeOutcome=hold-metadata-stale |
| Uncertain non-idempotent proposal submission | proposeOutcome=hold-proposal-uncertain |

Each line ends with one newline. The last outcome means GET-only verification
and HOLD; it is never mislabeled as stale metadata. This does not change C1's
per-effect law: uncertain exact metadata PATCH is GET-verified within this
invocation; a later invocation may apply ONE identical PATCH only after ALL
fresh predicates. Uncertain object, commit, ref, PR creation or publication
remains GET-only/HOLD across invocations; inferred absence never grants retry.

Technical failures do not become successful HOLD outputs. Missing actual
terminal/output commits, record-budget failures and partial local output
failures remain technical. Earlier native effect observations are retained;
neither provider effects nor local appends are retried. Partial persistence
can leave a line on disk while the invocation is technical. Business continuation
therefore requires BOTH the exact matched line AND the actual successful job
conclusion. Either negative line blocks continuation even after job SUCCESS.

The saved native record links selected result, whole terminal and local output.
Actual local save/reopen controls feed the bytes to the same native business
gate. Records and business signals are diagnostics only, never native terminal
admission, original-producer/current-writer permission, grants or release
readiness. Hosted output acquisition and trusted physical caller/old-process
proof, thin Foottrace bridge, same-core AF R0/RC-next adapter, current full gates
and independent full-source review/adoption remain owed. The writer-program executable facade exports only this fixed output entry and
uses the SAME implementation; the build emitter targets dist/propose-writer.cjs
with separately bound input/byte metadata and Node-only external imports. The
read-only inspection remains its distinct current physical contract. Compiled
programs are stale until the coordinated build and physical controls actually
complete. This does not admit a caller pin, physical writer or release authority.
